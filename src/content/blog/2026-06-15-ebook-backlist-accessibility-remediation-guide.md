A backlist repair brief needs more than a title and an error count. Before commissioning work, establish which file you hold, whether its editable source is available, and what remains unknown. The useful first deliverable is a catalogue register that assigns the next decision—not a spreadsheet that declares books accessible.

This guide proposes three provisional planning lanes for authors, rights holders and small production teams: repair sampling, specialist assessment, and source investigation. They are Rex Publishing's editorial synthesis, not official ABELab categories, cost bands or conformance scores.

## What the research supports

ABELab's [May 2024 final report](https://www.abelab.eu/outcomes/final_report/#how-to-triage-files) recommends collecting file format, other available formats, production information, source availability and editorial characteristics before triaging a backlist. We use that dated collection method as a starting point, not as evidence of current market conditions or tool performance.

Its [gap analysis, first published in 2023 and supplemented in 2024](https://www.abelab.eu/outcomes/gap_analysis/), distinguishes content complexity from remediation need and describes sampling and format-comparison limits. Our practical conclusion: neither subject category nor a raw error total should decide a title's place in the repair queue.

Two other references set boundaries. DAISY's [Ace guidance](https://inclusivepublishing.org/toolbox/accessibility-checker/getting-started/) says automated checks assist a wider human evaluation; they are not a complete accessibility assessment. W3C describes [EPUBCheck](https://www.w3.org/publishing/epubcheck/) as checking publications against EPUB specifications. A format-validation result and an accessibility review therefore belong in separate evidence fields, not one universal pass/fail column.

## Build the register around the next action

Give each file a stable internal ID and identify the exact copy being considered. Keep title and edition details in your working system; the neutral IDs below make the example easier to follow. If several files belong to one title, give them separate records and link them.

Record the format and layout, available production source, evidence date, report location, and the tool and rules versions actually used. Record the chosen format and accessibility targets separately. A target is what the team intends to assess against; a tool version describes how a particular report was produced. Write **unknown** or **not assessed** when evidence is missing. Do not turn an empty report field into zero errors.

Then add the unresolved content question, provisional lane, next action, owner and review point. The review point should describe what evidence will reopen the decision: a sample assessment, a source-file search result, or an editorial answer. A date alone does not explain what must change.

File A is not automatically the easiest job. Its lane makes a smaller initial question explicit: can a sample justify a bounded repair brief? File B needs a content judgment before that boundary can be drawn. File C needs a source search before anyone assumes reconstruction is the right commission. None of those decisions follows from format alone.

## Set priority separately from the lane

A lane describes the next kind of work; priority describes why that work should happen now. Keep a separate priority note grounded in reader or distribution need, source readiness and dependencies. Identify who owns that decision.

For example, a documented reader-access problem may justify commissioning File B's assessment before File A's sample. An available source may make a task ready to start, but it does not by itself make that title more important. If a dependency is unresolved, record it instead of disguising it as a low score.

When findings arrive, retain the earlier evidence and explain any lane change. Ask the reviewer to name the file examined, the scope covered, what remains uncertain, and the next decision required. An estimate can then refer to an agreed task rather than an assumed condition of the whole catalogue.

For format context, our [July 2026 EPUB baseline article](/blog/2026-07-15-epub-33-current-baseline-guide/) is dated background, not proof of today's production target. Confirm the specifications required for your actual commission and record them alongside, not in place of, tool versions.

Start with the files for which you need a decision. A useful row ends with a named role, an answerable question and a review point. It should make the next commission clearer without pretending the assessment has already happened.
